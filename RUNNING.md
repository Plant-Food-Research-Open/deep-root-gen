# Running DeepRootGen

Start with the [schema-4 workflow](docs/source/usage/native_workflow.rst)
and the [parameter reference](docs/NATIVE_EXECUTION.md). They cover the same
input in the CLI, Python, notebooks and the Simulation page. The
[model review guide](docs/MODEL_REVIEW_GUIDE.md) maps parameter ownership
and scientific review.

## Offline runtime and optional local services

Use Python 3.10 and install the existing Poetry lock with the development and
Torch groups. The graph code imports Torch and PyTorch Geometric when the
simulator loads. [Development guidance](docs/DEVELOPMENT.md)

## Offline checks

From the repository root, activate the locked Python environment or run the
commands through `poetry run`.

```bash
poetry check --lock
poetry build
CICD_TESTING_ENV=true python -m pytest -p no:cacheprovider --run-integration
flake8 --count --show-source --statistics
python -m deeprootgen simulate --config examples/synthetic_minimal.json --explain-config
python scripts/research/parameter_search.py --config examples/research/search_synthetic.json --outdir .runtime/search-new
python -m deeprootgen simulate --config examples/synthetic_minimal.json --outdir .runtime/synthetic-new
python -m sphinx -b html docs/source .runtime/sphinx-html
```

The search example validates its input. Use `--execute` to start a search.
Choose a new simulation output directory. Open `roots.html` to explore it in a
browser. Read `root_summary.json` for valid axis counts and contour lengths by
numeric order and for length and dry mass by diameter class. Use
`resolved_config.json` to see the active calculation for each order and
`run_manifest.json` to identify the seed, source and exported files.

Use the [offline migration command](docs/NATIVE_EXECUTION.md#migrating-an-existing-input)
to write a new schema-4 document from a historical simulation input.

## Optional local service recipe

`docker-compose.local.yaml` defines the loopback services and
`dockerfiles/python/Dockerfile.local` builds the local app image. Build the
current source under its own image tag. The first command below creates a
private `.env.local` with caller-generated credentials for local services.

```bash
python scripts/local/configure.py
docker build -f dockerfiles/python/Dockerfile.local -t deeprootgen-local:schema4 .
```

Set `DRG_LOCAL_IMAGE=deeprootgen-local:schema4` when starting a new local
Compose project with this image. Open **Simulation**, load a schema-4 fixture and
save edits through **Save parameters**. When the worker is running, follow the
run link until Prefect reports completion and retrieve its artifacts from
MLflow. For quick offline exploration, open `roots.html` generated by the CLI.

The **Docker Build** GitHub workflow also publishes the Dash and Prefect
runtime from a selected branch or published release. On the
`junqi108/deep-root-gen-PFR-open` fork, use the full Git commit SHA from the
successful workflow run in the following commands. The workflow summary also
provides the image digest for a deployment that pins the exact bytes.

```bash
COMMIT_SHA='replace-with-full-commit-sha'
export DRG_LOCAL_IMAGE=ghcr.io/junqi108/deep-root-gen-pfr-open:sha-${COMMIT_SHA}
docker pull "$DRG_LOCAL_IMAGE"
```

Use invented fixtures for dashboard and storage checks. Keep private
observations, fitted inputs, environments, credentials and run outputs in
their local research locations.

## Direct Python API


For in-memory Python use from the repository root:

```python
import json
from pathlib import Path
from deeprootgen.data_model import RootSimulationModel
from deeprootgen.model import RootSystemSimulation

spec = json.loads(Path("examples/synthetic_minimal.json").read_text())
params = RootSimulationModel(**spec)
model = RootSystemSimulation(
    random_seed=params.random_seed, simulation_tag=params.simulation_tag
)
model.run(params)
nodes, edges = model.G.as_df()
assert (len(nodes), len(edges)) == (11, 10)
```

installation was added or qualified. If using existing notebook tooling,

loopback). Ports and project name are examples; any unused values work, and
shell exports override `.env.local`. The default image tag changed from
`upstream-80315af` to `dashboard`; to restart the older `drg-upstream-check`
project unchanged, export `DRG_LOCAL_IMAGE=deeprootgen-local:upstream-80315af`.

**Status checks** (a page load, health check or listing is an intermediate
check only; a run is verified by its terminal state and artifacts):

```bash
$P ps -a                                      # one-shot jobs exit 0; others healthy/up
$P logs prefect-deployments | tail -1         # "Registered 7 dashboard deployments ..."
curl -s -X POST http://127.0.0.1:14203/api/deployments/filter \
  -H 'content-type: application/json' -d '{}' | python3 -c \
  'import json,sys; [print(d["name"], d["work_pool_name"]) for d in json.load(sys.stdin)]'
curl -s http://127.0.0.1:14203/api/work_pools/default | python3 -c \
  'import json,sys; print(json.load(sys.stdin)["status"])'   # READY = a worker is polling
```

`app/flows/prefect.yaml` is the only deployment manifest (the root
`prefect.yaml` is an unused scaffold). `prefect-deployments` upserts all seven
on every start and then fails unless each name used by the pages exists, so it
is safe to rerun: `$P up prefect-deployments`. Flows run with working directory
`/app/outputs`, the volume shared by app, worker and model services. The worker
imports calibrators into the Bento store at `/app/outputs/bento`.

**Recovery without data loss.** `$P restart app prefect-worker` for a stuck
page or worker; `$P up -d --wait` after a rebuild recreates containers on the
same named volumes (verified: Prefect runs and MLflow experiments persisted
across recreation). Re-register with `$P up prefect-deployments`. `$P stop` /
`$P start` pauses everything. Never add `-v`, prune volumes or regenerate
`.env.local` for an initialized project.

**Page feedback.** Every worker-backed page has **Check setup** (validates,
never submits) and **Run**. The results message stays until dismissed and
names the failure class: invalid form (with field names), *Prefect is
unreachable* and *Deployment missing* (nothing was submitted), *Submission
result uncertain* (retry with the unchanged form returns the same run, because
each send carries an idempotency key from a page nonce and the payload), or
*Queued* / *Already queued* with the run UUID and Prefect link, plus a warning
if no worker polls the pool. The run table's **State** column follows the run
and, on completion, names the MLflow run and its artifact count, or reports
missing artifacts; failed runs point to the worker log.

`scripts/local/dash_workflow_check.py` replays the guide's examples through
Dash's own callback endpoint (`--check-only` for Check setup) and
`scripts/local/dash_browser_check.mjs` drives headless Chrome with Playwright.
Verification results are in [the dashboard examples](docs/DASH_UI_EXAMPLES.md#verification-record-23-november-2026).

- **Wrong Python or missing Torch:** check `which python`, `python --version`
  and `python -m pip check` after activation. Use bootstrap; do not global-pip
  packages into system Python or widen the project's Python constraint.
- **Poetry mismatch:** use private Poetry 1.8.3; verify lock hash before changing
  dependencies. Do not regenerate the lock or replace Torch incidentally.
- **Docker denied:** use authorized task execution or the user's normal Docker
  setup. Never chmod the socket or widen persistent access.
- **Build download failures:** preserve logs, verify official registry/source
  availability and proxy settings; do not disable certificate verification or
  silently use an unofficial mirror. Initial builds need network and disk.
- **Port collision:** change only local port variables and restart. Keep all
  host bindings at 127.0.0.1.
- **UI unreachable or queued:** inspect `ps` and targeted logs for `app`,
  `prefect-server`, `prefect-worker`, `prefect-deployments`, `storage-init`.
  One-shot jobs should exit 0; worker must poll the default process pool.
- **Prefect UI cache permission:** retain PREFECT_UI_STATIC_DIRECTORY from the
  local Compose file. Do not make the entire Python installation writable.
- **Slow/large runs:** start with the tiny fixture. Profile generation and
  inference can be expensive; do not infer their capacity from this smoke test.
- **Missing results:** the Dash CSV is history only; use MLflow artifacts or
  the output-volume copy command. Check bucket readiness and worker failure.
- **Git SHA warning in container MLflow logs:** Git is absent from the image;
  use the separate source/runtime receipt, not an inferred MLflow code revision.
- **Exit codes after an explicit stop:** this Prefect CLI prints Aborted and
  exits 1 on SIGINT; MLflow may exit 143 on SIGTERM. Both were observed only
  during the requested final stop. A nonzero exit during startup or a running
  flow requires log inspection and is not an expected pass.
- **Changed database password:** restore the original private configuration for
  existing volumes; do not delete data as a troubleshooting shortcut.
